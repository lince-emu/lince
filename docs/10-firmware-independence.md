# 10 — Firmware and Key Independence

Status: Proposed plan under an Accepted decision (ADR-0029) · Last reviewed: 2026-11-13

## 1. The guarantee

**Lince runs games without console keys and without console firmware — always.**
There is no "firmware installed" mode, no key file, no detection of either, and no feature
that becomes available when they are present. The firmware-free path is the only path.

## 2. What this means for content (stated plainly)

| Content | Runs? | Why |
|---------|-------|-----|
| Unencrypted executables and data (loose ExeFS + RomFS, the layout used for development) | Yes | Nothing to decrypt |
| Homebrew built for the console | Yes, once its formats are supported | Homebrew is not encrypted |
| NSP whose NCAs are already decrypted (header and content in plaintext) | Yes | Lince only reads the PFS0 container and the plaintext NCAs; nothing to decrypt |
| Retail packages as distributed (NSP, XCI, NCA, …) | **No** | They are encrypted; Lince never decrypts (ADR-0029, LEGAL-02) |

Lince does not tell users how to convert encrypted content and does not link to tools that
do (LEGAL-03, LEGAL-04). The loader reports encrypted input, including any encrypted NCA
inside an NSP, with a neutral message and loads nothing from that package.

## 3. What games expect from the system, and how each need is met without firmware

Games call system services and read system data. Every item below is provided by an original
implementation, a freely licensed substitute, or a documented "unavailable" behavior. Evidence
levels as in doc 01: [EMU] observed by other emulator projects, [DOC] public documentation
(switchbrew) or a project's own documentation, [SRC] read in a project's source at a pinned
commit (as in `research/README.md`), [RECALL] known from Switch 1 emulation history, not
re-verified, [Inferred], [Unknown].

The full inventory, with the Switch 2 archive and applet ids, findings and citations, is
[`research/system-data-and-applets.md`](research/system-data-and-applets.md) (T-019). Approach
codes: **O** original implementation, **S** freely licensed substitute, **U** unavailable with a
documented result.

| Need | Typical use by games | Lince approach | Evidence |
|------|---------------------|-------------------|----------|

## 4. Rules for implementers

1. A missing system feature is implemented originally, substituted with freely licensed data,
   or reported as unavailable through the correct service error — never satisfied with
   firmware data (LEGAL-06).
2. Substitute data lives in `assets/system/` with its license recorded next to it (LEGAL-34).
3. Every system-data format implemented is documented in `docs/research/` from public or
   independently observed behavior (LEGAL-11 to LEGAL-13).
4. Tests boot titles and homebrew in the only mode that exists: no keys, no firmware.
