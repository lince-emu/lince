# ADR-0002: Build system — Cargo workspace + xtask

- **Status:** Accepted (maintainer, 2026-11-13)
- **Date:** 2026-11-13
- **Related:** ADR-0001, ADR-0026

## Context
Reference emulators use CMake with vendored C/C++ dependencies; build issues (path lengths,
compiler versions) consumed real time (Lichii `NX2_NOTES.md` rows 1–2). Lince is Rust-first.

## Requirements
One command to build and test on Windows and Linux; reproducible; no extra language for build
logic; generated assets (built-in SPIR-V) reproducible.

## Alternatives
1. Cargo + shell/PowerShell scripts.
2. **Cargo + `xtask`** (build automation written in Rust).
3. CMake/Meson wrapping Cargo.
4. Bazel/Buck2.

## Decision
Option 2. Built-in shaders are generated by Lince's own SPIR-V emitter (no external shader
compiler needed at build time); generated artifacts are checked in and verified by
`xtask ci`.

## Technical justification
Keeps the build in Rust, cross-platform, and avoids a second build language. Bazel-class tools
are not justified at this size.

## Advantages
Simple onboarding; same tooling for CI and developers.

## Disadvantages
xtask must be maintained; no built-in caching across machines (can add `sccache`).

## Risks
Foreign dependencies (ADR-0026) may need `cc`/`cmake` crates in build scripts; isolate them in
optional features.

## Validation plan
CI on Windows x64 and Linux x64 builds from clean checkout with `cargo xtask ci`.

## Conditions for revisiting
Clean build time > 15 minutes on CI or a dependency that cannot be built through Cargo.
